Docusaurus is a static-site generator for technical documentation. It supports Markdown, MDX, navigation, search, themes, and plugins.

In this codelab, you create a Docusaurus site, add a documentation page, configure sidebar navigation, preview the site, and build it for production.

By the end, you will have:

  • A local Docusaurus project
  • A custom page in docs/
  • A sidebar entry for the new page
  • A production build in build/

Before you begin, make sure that you have the following tools:

  • Node.js 20 or later
  • A terminal, such as Bash, zsh, or PowerShell
  • A code editor, such as VS Code

To check your Node.js version:

  • At the command prompt, run the following command.
    node --version

Use the Docusaurus initializer to create a site from the classic preset.

  1. At the command prompt, create a Docusaurus project.
    npx create-docusaurus@latest my-docs-site classic
  2. When prompted to choose a language, do one of the following:
    • To use TypeScript, choose TypeScript.
    • To use JavaScript, choose JavaScript.
  3. When prompted to choose a package manager, do one of the following:
    • To use the default package manager, press Enter.
    • To use another package manager, select the package manager.
  4. Change to the project directory.
    cd my-docs-site
  5. Install the dependencies.
    npm install

The classic preset includes the docs plugin, blog plugin, and default theme.

If npx fails behind a corporate proxy, configure your npm proxy settings, and then rerun the initializer.

Docusaurus keeps documentation content separate from site configuration.

The following folders contain the files that you edit most often:

Path

Purpose

docs/

Markdown and MDX documentation pages

src/pages/

Custom React pages, such as landing pages

static/

Static assets, such as images

The following files control site settings and navigation:

File

Purpose

docusaurus.config.ts

Site title, URL, plugins, and theme options

sidebars.ts

Docs sidebar navigation

src/css/custom.css

Global style overrides

To see how the generated site connects docs content to navigation:

  • In your code editor, open docusaurus.config.ts and review the docs preset option that points to ./sidebars.ts.

The sidebars.ts file controls which pages appear in the left navigation.

Create a page in docs/, and then link to it from the intro page.

  1. In your code editor, create docs/getting-started.md.
  2. Add the following content to docs/getting-started.md.
    ---
sidebar_position: 2
---

# Getting started

Welcome to the documentation site you created.

This page is in the `docs/` folder and is rendered automatically by
Docusaurus.
  3. In docs/intro.md, add a link to the new page.
    Read [Getting started](./getting-started).

The block between --- markers is front matter. In this example, sidebar_position controls the sort order among sibling pages.

To show the new page in the left navigation, update the sidebar configuration.

  • Open sidebars.ts and make sure that the tutorial sidebar includes getting-started.The file should match the following example:
    import type {SidebarsConfig} from '@docusaurus/plugin-content-docs';

const sidebars: SidebarsConfig = {
  tutorialSidebar: [
    'intro',
    'getting-started',
  ],
};

export default sidebars;

The string entries map to doc IDs that Docusaurus derives from filenames. The getting-started entry maps to docs/getting-started.md.

For larger sites, group pages into categories by using type: 'category' entries in the sidebar configuration. For more information, see the Docusaurus sidebar docs.

Start the development server to preview your changes with hot reload.

  • At the command prompt, start the development server.
    npm start

Docusaurus opens http://localhost:3000 in your browser. You should see:

  • The site homepage at /
  • The docs at /docs/intro and /docs/getting-started
  • The sidebar order from sidebars.ts

To verify hot reload:

  • Edit a Markdown file and save your changes. The browser refreshes automatically.

When you are ready to publish the site, create a production build.

  1. At the command prompt, create the production build.
    npm run build
    Docusaurus writes the output to the build/ directory.
  2. To verify the production build locally, start the local production server.
    npm run serve

You can deploy the contents of build/ to any static host.

Common static hosts include the following services:

  • GitHub Pages
  • GitLab Pages
  • Netlify
  • Vercel
  • Cloudflare Pages
  • Amazon S3
  • An internal web server

To deploy manually:

  • Upload the contents of build/ to your static host.

For GitHub Pages, Docusaurus also provides a deploy script.

  1. In docusaurus.config.ts, set url and baseUrl to match your hosting target.
  2. At the command prompt, deploy the site.
    npm run deploy

You now have a working Docusaurus documentation site. What to do next:

  • Add more pages under docs/ and expand sidebars.ts.
  • Customize branding in docusaurus.config.ts and src/css/custom.css.
  • Enable OpenAPI docs for API reference.
  • Set up a CI/CD pipeline so merges to main publish automatically.
